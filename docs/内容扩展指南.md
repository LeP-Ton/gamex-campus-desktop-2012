# 内容扩展指南

关联需求：REQ-20261106144937。新增内容优先通过数据定义，重要规则变化再扩展引擎指令。

## 新课程与专业

在 `src/content/world.ts` 中添加专业及课程：每门课提供稳定 ID、名称、学分、难度、教师风格、星期和开始分钟。同一专业不要有重叠课表，课程 ID 一旦进入存档不再改名。

新增专业时同步扩展 `Major` 联合类型、`MAJORS`、`COURSES`、特色题库、专业兼职和事件。校验器中的专业白名单与旧存档迁移也需要同步更新。UI 根据专业数据呈现，课程计算复用已有规则。

## 新 NPC

`NPCS` 中填写稳定 ID、姓名、成年年龄、身份、性格、兴趣、目标、习惯、三段日程、头像色与可恋爱性。需要特殊决定时，在 `systems/npcs.ts` 增加清晰的条件规则，不在组件里直接写数值。

新人物要有自己的活动与需求，不能只是一个聊天按钮。新增人物后，应为旧存档补齐人物状态与关系，并为主动消息添加符合角色的表达。人物数量变化会影响存档校验，不能直接把旧存档判成有效新存档。

## 新事件与事件链

事件模板位于 `src/content/events.ts`，必须包含：

- 稳定且唯一的事件 ID、名称、描述、类别与参与 NPC。
- 最早/最晚日期、当天出现分钟、有效时长、冷却时间。
- 可选专业、影响力、信任、前置事件与旗标条件。
- 至少两个有意义的选择，明确时间、金钱、精力成本与能力要求。
- 可计算的效果与后续旗标；有纪念物时提供收藏名称。

多阶段链使用相同 `chain` 名称、递增 `stage`、`previous` 前置节点和 `requires` 旗标。只有前置记录与旗标都满足，后续才会出现。不要把每个按钮拆成独立事件来凑数量；重要分支可以新增模板并通过不同旗标分流。

普通效果通过 `EventEffect` 复用资源、知识、关系、旗标和物品。需要赛事结算、信息传播或特殊课程行为时，为该规则写系统函数并添加测试。处理拒绝、时间不足、精力不足和过期的情况。

## 新专业练习

在 `src/content/challenges.ts` 中添加稳定 ID、类型、标题、题干、可选代码、候选答案、正确索引与中文解析。UI 不向引擎传递“是否答对”，只发送题目 ID 与所选索引，由引擎校验。

题目应符合大一基础知识。开放式代码执行或更复杂的结构拖拽需要独立小游戏状态和指令，不应在 UI 定时器里发放知识奖励。

## 新娱乐应用

现有竞技玩法的状态机与选项在 `systems/competition.ts`。新增 FPS、动作或休闲游戏时，新建自己的局内状态与指令，仍通过统一 `spend/advance` 扣时间和精力。等待、暂停、正式操作和中断损失必须明确定义。

新增桌面应用时补充 `AppId`、`APPS` 元数据和 `Apps.tsx` 的组件路由。所有图标有可访问名称，应用支持小屏滚动，不把重要操作藏在不可见的窗口外。

## 新称号与排行榜

称号在 `systems/settlement.ts` 中依据实际结果判断。每个称号写出明确阈值，互相矛盾的称号使用互斥条件。同类成长不能无上限叠加，不用一个总分概括全部人生。

本地榜单从 `SemesterResult.ranking` 独立读取六维成绩。未来联网实现 `LeaderboardProvider`，明确标识数据范围与访问权限，不能把本地记录称作全国或全网排名。

## 后续学期与存档迁移

目前 `semester=1`、112 天和关键日数组属于首版内容。扩展时建议引入学期定义表，配置起始日期、天数、关键日、课程、事件和基础生活成本。

保留既有学期档案，迁移玩家累计能力、物品、长期记忆和重要关系，同时重置本学期课程与计数。新增或改变字段时提高存档版本并提供显式迁移函数，不能静默丢弃旧用户进度。毕业评价应从八学期真实轨迹计算。

## 提交前验证

至少检查同种子回放一致、异常成本被拒绝、事件前置与截止时间正确、存档导出再导入一致、两专业能够结算。重大平衡修改运行七种策略模拟；新应用增加必要的 Playwright 交互验证。将实际结果、未验证项和 Git 定位记录到所属需求阶段文档。
