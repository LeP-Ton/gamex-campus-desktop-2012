# 游戏架构说明

关联需求：REQ-20261106144937。首版为浏览器本地规则驱动的单人游戏，不依赖外部 API。

## 状态与单向指令

`src/engine/types.ts` 定义完整的世界状态 `GameState` 和可执行指令 `Command`。状态包含玩家、专业、学期、日期、分钟、资源、课程、NPC、人物关系、记忆、承诺、消息、动态、事件、竞技对局、日记与人生轨迹。

UI 只通过 `src/stores/gameStore.ts` 发送指令。引擎入口 `dispatch(输入状态, 指令)` 会复制状态、校验条件、扣除成本、推进时钟、计算效果并返回新状态。引擎不调用 DOM、localStorage、系统时钟或 `Math.random`，相同输入可复现相同输出。

窗口位置、大小、层级与开始菜单属于桌面呈现状态，由 `desktopStore` 单独管理，不参与世界随机性或考试结果。关闭、最小化应用不会撤销已经发生的行动。

Windows 7 桌面在 `components/desktop`；`PeriodSocial.tsx` 分别实现 QQ2012、人人网和 QQ空间，`PeriodGames.tsx` 实现英雄联盟旧客户端与盒子，`BrowserChrome.tsx` 提供 IE9 外框，`period.css` 管理时代界面样式。软件之间共享引擎状态，头像、装备、原画和壁纸均从本地 `public/period-assets` 加载；资料来源见 [界面参考](2012界面参考与素材.md)。

## 一个世界，一只时钟

绝对游戏时间为 `day * 1440 + minute`。上课、聊天、学习、兼职、约会、匹配和比赛均使用这只时钟。

每次有时间成本的操作先检查学期状态、注意力、剩余时间、精力和金钱，再推进分钟。正式竞技对局会阻止其他需要注意力的行动；等待匹配允许聊天，达到匹配时间后变为待接受，超过宽限期会取消并扣分。消息和事件期限通过绝对游戏时间判断，不使用独立现实计时器。

读取消息、查看界面、保存、编辑生活计划不扣游戏时间。私人日记属于记录功能，不产生属性收益。现实时间只作为存档元数据，既不影响考试也不影响随机事件。

## 关键日与背景日

一个学期 112 天，预设 28 个关键操作日。结束今天时先结算出勤、每周作业、知识遗忘和基本生活费，再进入下一天。

遇到背景日时，按生活计划计算真实行为：按课表出勤、按薄弱课程学习、轮流完成作业、竞技训练、兼职收入、社交和休息；随后推进人物的情绪、需求、能力、人物间关系与消息。新出现的重要后续事件会停止快进，升级为操作日。

每日基本生活费为 12 元，每 28 天到账 650 元。初始金额为 800 元。金钱不足会影响恢复，但不立即结束游戏；可以使用免费休息和普通兼职补救。

## 学业与专业

学习收益由时长、精力、知识基础、专业理解、课程难度、复习间隔和同日收益递减共同决定。医学系对间隔复习更敏感。每门课都有独立掌握度与出勤/作业记录。

学期末单独计算考试表现，总评为考试 60%、出勤 20%、作业 20%。考试受掌握度、专业理解、疲劳和距上次复习的时间影响，统一随机数只提供有限幅度的发挥差异。不能只用单一“学业值”代替课程成绩。

专业练习校验题目 ID 和真实答案，题目推进与每日上限写入状态。答错有订正收益，答对收益更高。专业专属兼职和事件另有能力要求。

## 人物、社交与信息

NPC 每日根据性格、目标、日期和日程调整活动、情绪、能力与需求，独立推进与其他人物的关系。近期记忆有长度限制，重要经历进入长期记忆。

玩家关系包含熟悉、信任、兴趣契合、共同经历、履行承诺与冲突。聊天不奖励机械追求最快回复，明确说明没空也能保留信任；相同人物同日聊天与活动都有上限。表白需要多个条件，考前压力与情绪会影响邀约。

承诺在期限内通过相应活动履行，否则损失信任。恋爱关系也会因长期缺少沟通而恶化或结束。所有恋爱角色均为成年人，教师不参与恋爱系统。

公开校园活动产生公开动态；宿舍矛盾的影响按熟人关系传播，玩家动态的回应来自已有熟人。没有“全部人物瞬间知道所有私事”的统一全局好感度。

人人网与 QQ空间复用动态规则，按类别和作者筛选。QQ空间自己的日志来自玩家日记，NPC 的空间不读取玩家日记或个人收藏；空间留言通过已有的聊天指令发送给本人，人物关系仍由统一规则处理。

## 事件与竞技

`content/events.ts` 提供模板和选择，`systems/events.ts` 判断专业、日期、时段、关系、能力、前置记录和旗标。种子会改变部分机会的最早出现日。选择成本可检查，超过时窗不能完成选择。三十个节点构成十条多日事件链，前置选择会决定后续是否发生。

竞技使用排队、待接受、对线、资源争夺、团战状态机。位置与英雄适配、个人能力、精力、战术积累、队友信任和对手强度共同影响胜率。退出和错过匹配有明确损失。校园赛结果由能力与团队条件计算，生成实际轨迹与论坛讨论。

英雄资料位于 `content/league.ts`。所选英雄以可选 `champion` 字段写入对局与战绩，旧存档缺少该字段时使用默认展示，不重算既有结果。盒子直接读取同一份战绩，资源提示设置独立保存在本机，不参与随机数或竞技数值。

## 存档与确定性

`random.ts` 是世界中唯一的伪随机数入口，初始种子散列与当前随机数状态同时保存。`save.ts` 负责版本封装和结构校验；`gameStore` 负责存取浏览器数据。

每次操作后保存完整状态。导入先校验，失败时保留当前游戏；开始新局或成功导入前备份当前存档。补考重建同一局的结算，替换该局历史记录，避免重复刷榜。每局的 `runId` 仅用于区分历史归档，由浏览器生成，不参与规则或世界随机性；同种子重开也可以分别留档。

生产构建递归收集静态资源，并按文件内容生成 Service Worker 缓存版本，首次加载后保存全部静态资源。离线不影响规则、存档或 NPC。新构建通过缓存版本切换清理旧资源，已有页面切换到新界面，localStorage 进度保留；首次访问不主动刷新。开发环境不注册离线缓存，避免影响热更新。

## 结算与扩展边界

结算根据实际课程、资源、关系、轨迹和成就生成多个兼容称号，六榜独立评分。回忆来自历史记录，未经历的故事不会被补写进去。

`SemesterResult` 保留学期编号，后续八学期应在内容层新增学期定义与跨学期迁移。`LeaderboardProvider` 是未来联网榜单入口；`NPC_PROVIDER_CONTRACT` 规定未来模型只能返回校验过的文本，不能直接修改规则状态。首版实际使用本地实现，没有隐式联网服务。
