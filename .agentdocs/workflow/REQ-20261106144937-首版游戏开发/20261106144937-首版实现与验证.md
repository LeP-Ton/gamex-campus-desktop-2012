## 目标与决策

按用户完整需求建设首版，优先保证新建角色至学期结算可运行。统一种子与分钟时钟；应用窗口不拥有独立的世界计时器；28 个预设关键日结合实际背景日模拟；事件内容数据驱动。桌面与壁纸原创，采用时代感配色和 Aero 窗口。

## 修改与验证

### 主要变更

- `src/engine`：完整世界类型、统一随机数、指令处理、时钟、创建角色、成本校验、背景日、存档校验。
- `src/systems`：多因素学习、独立考试、NPC 自主日程与人物间关系、记忆与承诺、事件前置与期限、三阶段竞技、学期结算、六类独立榜单。
- `src/content`：两专业及课程、八名 NPC、生活计划、专属兼职、44 个事件和十条跨日期链、12 道专业题。
- `src/components`、`src/styles.css`、`public/`：十二个实际应用、Aero 桌面、开始菜单、任务栏、多窗口、原创建筑壁纸、入学界面与响应式适配。
- `src/stores`：UI 与规则入口解耦，自动保存、备份和恢复，独立的每局归档 ID，防止相同种子重开覆盖其他局榜单。
- `vite.config.ts`：生产版离线缓存，首次缓存完成后断网刷新可用；开发环境不注册缓存。
- `src/tests`、`e2e`：引擎与内容验收、两专业七策略对照、完整浏览器流程和生产离线测试。
- `README.md`、`docs/`：启动、玩法、实现功能、架构、扩展和已知边界；根目录长期规范与需求索引。

### 实际发现的问题及修复

1. 默认 npm 内网源在沙箱中不可解析，公共源连接也超时。已实际探测并使用可访问镜像安装依赖，未改变用户全局 npm 配置。
2. 第一次构建发现无意义的 CSS 空导入无法解析，删除后构建通过。
3. 初轮 22 项基础测试通过，但策略对照发现契合度固定会使部分关系永远无法发展。改为真实相处逐步增加契合，保留信任、熟悉、共同经历与情境要求。
4. 早期背景学习过快，多个路线得到相同成绩；降低学习系数并加强掌握度边际递减后，学业、娱乐和兼职路线出现可解释差异。
5. 自动化读取桌面按钮时，装饰箭头和未读数字进入名称，导致定位失败；补齐明确的可访问名称。
6. 浏览器已走通功能后，两条断言因多窗口同名元素出现选择器歧义；将断言限定在任务栏或榜单窗口，实际拖动、缩放和结算均通过。
7. 新增的真实断网测试发现预览服务器 `Vary: Origin` 使模块资源无法匹配预缓存。仅对同源静态缓存忽略该差异，断网刷新后课程操作通过。
8. 梳理归档发现同种子相同姓名可能产生相同档案 ID；新增不参与世界规则的每局标识，并在补考时更新同一档案。
9. 链式首个邀请可能出现在背景日；首节点和后续节点均可升级为关键日，避免关键机会被自动快进吞掉。
